# Pi terminal visual matrix

**Status:** Predeclared matrix; reference captures pending. The existing Pi TUI is the visual authority for nox. A green functional test does not prove a visual match. No intentional departure is approved; any proposed departure requires a constitution amendment before implementation (FR-003).

The first frozen component capture is `packages/coding-agent/test/__snapshots__/pi-visual-baseline.test.ts.snap`, generated from the unchanged Pi renderer on `main` at `484817a55` and checked by `packages/coding-agent/test/pi-visual-baseline.test.ts`. It records raw ANSI for the built-in read-tool request, collapsed and expanded success, missing-file error, and denied-result card with synthetic `notes.txt` input at 1, 40, 80, and 120 columns in dark and light themes. This covers only the card itself; it does not capture the full terminal, cursor, permission prompt, recovery, or other tool cards. The matrix below remains open.

The first frozen full-terminal snapshot is `packages/coding-agent/test/__snapshots__/pi-terminal-baseline.test.ts.snap`, generated from the Pi renderer at `0238c1144` and checked against future renders by `packages/coding-agent/test/pi-terminal-baseline.test.ts`. It records raw ANSI writes, visible 24-row viewport, and cursor position for the read request, missing-file error, and a new successful read card after that error at 40, 80, and 120 columns in both themes. This is a visual retry sequence using synthetic tool results, not a provider-backed recovery observation. At 1 column, this pre-change Pi path throws `Rendered line 2 exceeds terminal width (2 > 1)` before a valid full-terminal frame can be captured; the component-level 1-column frame above remains available. The terminal boundary and all other workflow states remain open.

The trust-selector snapshot is `packages/coding-agent/test/__snapshots__/pi-trust-terminal-baseline.test.ts.snap`, checked by `packages/coding-agent/test/pi-trust-terminal-baseline.test.ts`. It freezes ANSI writes, 24-row viewport, and cursor position for an untrusted synthetic `/project` at initial focus and after moving focus to “Do not trust,” at 40, 80, and 120 columns in both themes. It captures selection presentation only; accept/decline persistence and restart behavior need separate scenarios.

For each affected row, render the pre-change Pi revision and the candidate nox revision from the same disposable session, settings, terminal size, and action sequence. Save normalized terminal frames or ANSI transcripts with the revision and fixture. Compare visible text, wrapping, alignment, borders, colors, emphasis, cursor placement, focus, scroll position, and feedback timing. Normalize only volatile paths, timestamps, IDs, and terminal escape sequences that do not change appearance; never normalize missing controls, text, colors, or layout.

The width sample is 1 column (rendering boundary), 40 columns (narrow), 80 columns (default fallback), and 120 columns (wide), plus any width where a touched component changes its layout. Both built-in `dark` and `light` themes are required. A changed custom-theme behavior also requires its own fixture. Terminal height is 24 rows by default and 10 rows for overflow/scroll states. This finite set probes width behavior; a discovered breakpoint must be added before the owning source change.
